# Kaoru v0622.3 真机验收清单

适用版本：`0622.3`，`versionCode=6`，数据库版本仍为 11。
安装包：工作区 `dist/Kaoru-v0622.3-debug.apk`（debug 签名）。

## 本轮行为

- 开播、标题／分区变化：优先打开 B 站客户端直播间，再尝试网页，最后回到应用。
- 单条下播：打开该主播的直播历史，并标记、滚动到通知对应场次。
- 批量开播／下播：先显示本批成员；点成员后打开直播间／对应历史。
- 封禁变化：主播详情。系统异常／恢复：诊断页。
- 原始记录清理后：尝试使用通知中的轻量目标快照；无法定位时给出提示并打开通知历史。
- 通知不再等待整轮监控完成或封面下载；聚合仍需等待当前配置的窗口，默认 5 秒。
- 新增“通知有效期”：开播默认 5 分钟、下播 10 分钟、标题／分区变化 3 分钟，可在设置修改。
  系统状态提醒 5 分钟，封禁变化 10 分钟。过期或已被新状态替代的提醒不再补发，历史仍保留。
- 点击、划去通知会留下交互确认，避免投递结果未知时重新补发。
- 实时模式按开始时间安排下一轮，长轮次跳过错过的时点，不集中补跑。
- 亮屏、无网络、无监控对象时释放额外 CPU 唤醒锁；网络恢复后重新检查。
  **锁屏且联网的本地实时监控仍需要持续唤醒锁，无法保证接近正常深睡的待机功耗。**

## 测试条件

记录手机型号、Android／系统版本、B 站客户端版本，以及监控模式、间隔、确认次数、
监控人数和 Root／Shizuku 档位。先保持原有配置测试，再调整单项进行比较。
有效期设置属于本机 DataStore 偏好，目前不包含在应用的数据备份中，换机时需重新设置。

## 1. 通知跳转

在自然出现相应事件时检查；不必为了测试更改主播的实际直播状态。

| 项目 | 预期 | 结果／备注 |
|---|---|---|
| 应用关闭界面时点单条开播 | B 站客户端的正确直播间 | |
| 应用已打开时点另一位主播通知 | 打开新通知对应主播，不被上一次点击覆盖 | |
| 连续点不同通知 | 最后一次点击对应的目标正确 | |
| 点单条下播 | 主播历史页，对应场次带“通知对应场次”标记 | |
| 点批量开播，再选择第二位主播 | 先显示完整成员列表，再打开所选直播间 | |
| 点批量下播，再选择不同成员 | 进入所选主播的对应历史 | |
| 点标题／分区变化 | 正确的直播间 | |
| 点封禁／解封 | 正确主播的详情 | |
| 点系统异常／恢复 | 进入诊断页 | |
| 点击后旋转屏幕、切回应用 | 不重复打开网页或反复跳转 | |
| 未安装／禁用 B 站客户端的设备 | 网页回退有效；浏览器也无法打开时进入应用 | |

“通知点击能打开客户端”仍受 B 站客户端自身的深链支持影响，需用你的实际客户端验证。

## 2. 延迟、过期和重复提醒

| 项目 | 预期 | 结果／备注 |
|---|---|---|
| 正常联网出现开播变化 | 确认变化后尽快投递；启用聚合时允许默认 5 秒窗口 | |
| 部分主播请求较慢 | 不拖住其他已经确认的通知 | |
| 弱网或封面地址较慢 | 文字提醒不等待图片 | |
| 断网后恢复 | 恢复检查；已经下播的旧开播提醒不作为“正在直播”补发 | |
| 通知权限关闭期间产生事件，超过有效期后授权 | 旧提醒不再弹出，可在通知历史看到取消／过期原因 | |
| 单独关闭通知渠道，再开启并返回应用 | 有效期内仍有意义的提醒恢复；过期消息不补发 | |
| 划去通知后继续等待 | 同一条不重新出现 | |
| 点击通知后返回应用 | 同一条不重复响铃 | |
| 批量通知中的部分主播已结束／被暂停 | 发送前移除失效成员，显示人数与成员一致 | |

轮询式监控无法知道平台尚未返回的变化。确认次数大于 1 会增加确认周期；
省电模式的系统调度至少 15 分钟，还可能延后。请分别记录“应用确认变化时间”和“通知出现时间”，
不要把主播真实开播时间与本地确认时间混为一项。

## 3. 锁屏与功耗

先做 30–60 分钟测试，通过后再做整夜比较。比较时保持监控人数、检查间隔、网络、
Root／Shizuku 档位一致，拔掉充电线，并尽量减少其他应用活动。

| 项目 | 预期 | 结果／备注 |
|---|---|---|
| 实时模式＋锁屏继续活跃，锁屏 30–60 分钟 | 继续检查并接收有效通知 | |
| 亮屏查看高级保活状态 | 显示亮屏无需额外唤醒锁，未持锁属于正常状态 | |
| 锁屏且联网 | 实时模式按配置持锁；不能以省电为由停止检查 | |
| 断开所有网络 | 释放唤醒锁，避免无效请求；恢复网络后重新检查 | |
| 暂停全部主播 | 不再为零监控对象保持 CPU 清醒 | |
| 切换省电模式 | 不持有实时模式唤醒锁；检查间隔由系统调度 | |
| 关闭监控 | 常驻服务停止，唤醒锁释放 | |
| 整夜测试 | 记录耗电百分比、系统电池页的后台耗电与通知实际延迟 | |
| 厂商最近任务清理、Root／Shizuku 保活 | 在你的 ROM 上确认实际效果 | |

系统设置中的“强行停止”会阻止自动恢复，这是 Android 的边界，需要用户重新打开应用。
本轮没有接入服务端或云推送；锁屏联网实时监控仍有持续待机成本。
