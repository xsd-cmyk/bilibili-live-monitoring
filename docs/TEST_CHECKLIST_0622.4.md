## 优先测试

| 项目 | 操作 | 预期 | 结果 |
|---|---|---|---|
| 升级 | 覆盖安装，打开历史和设置 | 主播、历史、备注、设置保留，无启动异常 | |
| 恢复到实时 | 当前省电，恢复一份实时模式备份 | 按当前保活选择启动实时监控；权限不足时明确降级 | |
| 恢复到省电 | 当前实时，恢复省电模式备份 | 常驻服务和实时唤醒锁停止，系统周期任务接管 | |
| 恢复为关闭／手动 | 恢复相应备份，等待并查看后台状态 | 不再继续自动监控 | |
| 维护竞争／取消 | 导出时返回页面，再尝试导出或清理 | 可继续使用，监控不会永久停在维护中 | |
| 备注 | 仅修改备注，再查看时间／置信度 | 原时间、来源与保护状态不被修改 | |
| 清空备注 | 删除备注文字并保存，重新打开 | 备注保持为空 | |
| 历史 | 搜索很早的日期或旧标题；滚动到末尾加载更多 | 老记录仍可找到，统计不因最近记录多而变零 | |
| 批次部分失败 | 遇到部分主播请求失败时观察其他成员 | 已有新鲜状态的成员先提醒，待复核成员不重复提醒 | |
| 通知点击 | 开播、单条／批量下播、标题变化、封禁、系统状态 | 落点符合 0622.3 清单 | |
| 待发通知改时钟 | 有待发提醒时前／后调整系统时间，再恢复 | 同次开机不因此立即过期或长时间推迟重试 | |
| 诊断数字 | 暂停／恢复一位主播，再进诊断 | 监控人数及时更新；在播／封禁数字随状态刷新 | |

## 资源与长期运行

| 项目 | 预期 | 结果 |
|---|---|---|
| 离开历史页或锁屏 | 5 秒后停止该历史页的数据库订阅和映射计算 | |
| 每日维护 | 仅充电且电量充足时由系统低频执行；监控租约有效时避让 | |
| 亮屏／离线／暂停全部主播 | 额外 CPU 唤醒锁按实际条件释放 | |
| 锁屏联网实时运行 30–60 分钟，再做整夜比较 | 功能继续；记录实际通知延迟与耗电 | |
| Root／Shizuku 和厂商任务清理 | 在实际设备上核对生效状态及恢复情况 | |

锁屏联网实时监控仍需持续唤醒锁，不能保证接近深睡功耗。系统“强行停止”后需要重新打开应用。
备份输入／输出统一限制 64 MiB；未知文件大小也会受实际读取限制。有效期偏好仍保存在本机，未纳入备份。

反馈时提供手机型号、系统版本、监控模式／间隔、事件类型、应用确认时间、提醒出现时间、
实际跳转页面及是否锁屏／离线；异常发生后导出诊断包。耗电反馈请附测试时长和系统电池页记录。
