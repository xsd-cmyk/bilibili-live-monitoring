# 0622.13 · 一级页、预测性返回与全玻璃帧测试

## 怎样测

- Windows，JDK 17，Gradle 8.11.1；专用 Android 15 / API 35 x86_64 AVD、60Hz，Android Emulator 的 host GLES（NVIDIA GeForce RTX 5060 Laptop GPU）。`0622.12` / 15 和 `0622.13` / 16 为同包名、同证书的 debug 构建。未使用用户备份、账号或实体手机。
- 仪表化回归使用生产 `PageNavHost`，用 `PixelCopy` 在窗口中采样，不只判断目标路由。欢迎页出栈后，在首页与设置间双向观察两种互邻且无底色的色块；转场途中改选，验证最终路由、首页锚点及重选不会入栈。返回在 0.18 与 0.65 进度检查可见面积增大且栈顶未变；分别测试左侧撤销、右侧提交。
- 性能场景使用同一张彩色合成壁纸、91 条列表数据（其中 90 个 Studio 合成条目）、关闭监控、浅色、Dock 与卡片液态玻璃同时打开，不改用户数据。独立测 **0 dp**（透明偏好）和 **28 dp**（默认模糊）。1080×2400 / 480 dpi，手势导航。每次先打开首页，确认 Studio 01、四个底栏入口和实际偏好，再预热一次导航循环与上下滑。
- 每个模式各 3 轮：一轮切页为「历史→统计→设置→主播」×2、每次停 0.42 秒；滚动为 410 ms 上、下滑各 3 次，各停 0.7 秒。每个场景前重置 `dumpsys gfxinfo`，取系统的 Total frames rendered、Janky frames、P50、P95；P95 汇总为三轮中位数，慢帧比例按三轮总数加权。数字不是平均 FPS，也不是功耗测量。
- 复测入口：[measure_frames.py](measure_frames.py)。用合成测试机按上面准备后运行 `python measure_frames.py --serial emulator-5748 --blur 0`，再用 28 重测。用 `--adb` 可以指定 SDK 路径。脚本不更改外观，不导出账号或业务记录。

## 边界与排查记录

- 中间版本只共享全分辨率滤镜：静止页面材质正确，但 28 dp 的切页 P95 三轮中位数仍达 65 ms，高于旧版的 57 ms，未作为交付版。最终版对静态壁纸预处理并在 GPU 录制完成后缓存，28 dp 对应 1080×2400 的输入缩至 270×600；不会把动态 Dock 或页面文字冻住。新增设备断言等待实际纹理就绪，检查卡片内红蓝分界柔化、卡片外仍锐利。
- 旧版在 API 35 系统手势模式从详情左右两侧拖至相同距离，两侧都显出左侧的上一页；取消可留在原页，所以单纯断言“最终返回成功”抓不到这个问题。2.8.5 的预览取消阶段也不会像 2.8.9 一样保留正在回退的目标内容。采用同系列稳定依赖，不新增并行的返回处理器。
- 先用 720×1600 检查端到端流程；SwiftShader 退出、新旧包在暂停监控/多次冷启动时的 `MonitoringService` 前台服务启动超时均不计为有效样本。并行编译时 1080 测量波动很大，不能用于宣称提速；最终对比与这些探索记录分开。JVM 回归曾在 `CircuitBreakerConfigTest` 的 `declaredConstructors.first()` 遇到反射顺序波动，未为使导航发布过测而改动数据库或该断言。
- 只对实际测过的模拟器作结论，不推断厂商手势、120 Hz 真机、低端 GPU 或 API 31/32 性能。零模糊不加磨砂；有模糊时共享的是供卡片采样的壁纸层，页面壁纸本身不被强制模糊。
